# 需求变更执行记录

本文档记录后续修改如何按预期工作流执行。详细规则见 `docs/09_change_management_standard.md`。

## 使用要求

- 每次受管修改开始前新增一条记录。
- 实施前填写需求、等级、验收标准、影响范围和重跑起点。
- 实施后逐项更新完成情况。
- 存在未完成项或失败项时，状态不能写为“已完成”。

## 变更记录

### CHANGE-20260713-01：完善后续修改工作流

- 状态：已完成
- 变更等级：L3
- 需求：审核现有方案，并调整项目规范与模板，确保后续修改按完整工作流执行。
- 验收标准：后续修改必须先登记、判断影响、执行受影响流程、完成校验并同步最终产物。
- 影响范围：项目入口、工作流规范、业务框架模板、Notebook 规范、问题日志和交付审计清单。
- 最早执行位置：框架规范。
- 必须执行到：规范、模板和检查清单完成同步。
- 业务框架同步：不适用，本次修改的是通用框架。
- 报告结构同步：不适用，本次不修改具体分析报告。
- 受影响文件修改：已完成，项目入口、工作流、业务框架模板、Notebook 规范和交付审计已同步。
- 相关检查：已完成 Markdown 围栏与行尾、Notebook JSON、Python 语法和跨文档旧规则残留检查。
- 完整 Notebook 运行：不适用，当前仓库为模板且没有具体分析数据。
- 剩余风险：本方案采用轻量人工流程，不做自动门禁；后续 Agent 必须遵循 `agent.md` 和第 09 号规范。
