# 结果呈现型数据分析报告（结论摘要）

本文档是脚本生成的结论摘要应遵循的结构说明。具体项目交付时，摘要由 `scripts/generate_final_report.py` 生成到：

```text
reports/final/final_analysis_report.md
```

完整分析过程不在本文件中展开，而是写入：

```text
reports/final/analysis_detail.html
```

结论摘要只保留以下内容：

- 元数据与运行 ID。
- 核心结论。
- 关键指标。
- 关键图表。
- 交付物索引（链接到 HTML 章节）。

逐业务问题的分析逻辑、证据、图表、结果表、口径与限制、数据质量和复现细节全部放在详情页。详情页的每个业务问题章节和每个过程章节也必须写清本节结论，结构与要求见 [analysis_detail_report_template.md](analysis_detail_report_template.md)。

## 1. 元数据与运行 ID

报告开头必须包含：

- 报告标题。
- 生成时间。
- 运行 ID。
- 分析框架路径。
- 报告结构路径。
- 主 Notebook 路径。
- 完整分析过程 HTML 路径。

运行 ID 使用固定格式，供报告绑定校验：

```markdown
- 运行 ID：`<run_id>`
```

## 2. 核心结论

集中呈现本次分析最重要的结论，通常 3 至 7 条。

要求：

- 每条结论必须是可复核的事实性结论，不写空泛判断。
- 涉及数字时引用注册指标 ID 或关键指标表。
- 不在摘要中展开分析步骤；需要过程时链接到详情页对应章节。
- 默认不生成洞察、归因或业务建议。

## 3. 关键指标

以表格呈现最重要的核心指标：

| 指标 | 结果 | 说明 |
| --- | --- | --- |
| 指标名称 | 数值 | 口径说明 |

要求：

- 指标必须来自 `configs/project_contracts.yaml` 注册的指标 ID。
- 数值必须与结果表单元格一致，生成前由脚本对账。
- `format: percent` 只控制显示，不改变计算值。

## 4. 关键图表

只放最关键的图表，通常 1 至 3 张。

要求：

- 图表文件位于 `reports/figures/`，摘要中使用相对路径引用。
- 图表必须有标题和图注。
- 全量图表放在详情页，不在摘要中堆砌。

## 5. 交付物索引

列出详情页入口和主要章节链接：

```markdown
- [完整分析过程（HTML）](analysis_detail.html)
- [Q1：业务问题一](analysis_detail.html#q-q1)
- [数据质量与清洗](analysis_detail.html#detail-d1)
- [附录：口径、限制与复现信息](analysis_detail.html#appendix)
```

要求：

- 链接必须指向实际存在的 HTML 文件和锚点。
- 章节锚点由详情页渲染器固定生成，不手工拼接。
- 不在摘要中重复详情页的图表清单和结果表清单。

## 6. 禁止内容

结论摘要中不得出现：

- 逐业务问题的“分析逻辑”“分析过程”“图表清单”“结果表清单”“口径与限制”长段落。
- 数据质量检查明细、清洗规则、字段说明和复现命令。
- 未完成占位内容。
- 未脱敏敏感明细。
- 默认由大模型生成的洞察、归因或业务建议。

完整过程、证据和每节结论统一放在详情页。
