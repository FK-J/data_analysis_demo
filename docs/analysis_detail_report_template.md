# 分析过程详情页（HTML）结构说明

本文档说明脚本生成的详细分析过程页应遵循的结构。具体项目交付时，详情页由 `scripts/generate_final_report.py` 根据 `reports/final/report_inputs.yaml` 生成到：

```text
reports/final/analysis_detail.html
```

详情页承载**完整分析过程**：分析框架、数据范围与质量、清洗与特征、EDA、逐业务问题分析、证据、全量图表和结果表、稳健性、方法假设、口径限制和复现信息。结论摘要 `reports/final/final_analysis_report.md` 只保留元数据、核心结论、关键指标、关键图表和指向本页的交付物索引。

## 1. 页面结构

详情页按以下顺序组织：

1. **页头与元数据**：报告标题、生成时间、运行 ID、分析框架、报告结构、主 Notebook，以及返回结论摘要的链接。
2. **目录**：链接到分析概览、各业务问题、各过程章节、附录与复现信息。
3. **分析概览**：核心结论、关键指标、关键图表。
4. **业务问题分析**：按 `business_questions` 逐项展开。
5. **详细分析过程**：按 `detail.sections` 展开数据质量、清洗、EDA、稳健性、方法假设等跨问题章节。
6. **附录与复现信息**：数据范围、指标口径、输出文件、报告要求覆盖、运行 ID、Notebook、分析框架和报告结构路径。

## 2. 每个业务问题章节必须包含

每个 `Q1`、`Q2` 章节都必须有以下小节：

- 本节目标。
- **本节结论**：至少一条，能追溯到图表、结果表或证据文件；不能只写“详见分析”。
- 分析逻辑。
- 分析过程：建议使用 `process_steps` 记录步骤标题、方法/口径、证据文件和本步骤结论。
- 核心指标，若本节有注册指标。
- 图表。
- 结果表。
- 口径与限制。

## 3. 每个过程章节必须包含

每个 `detail.sections` 章节都必须有以下内容：

- 章节标题。
- **本节结论**：至少一条。
- 分析说明或分步过程。
- 相关图表和结果表，若存在。
- 口径与限制，若存在。

## 4. HTML 技术要求

- 使用 UTF-8 编码，`lang="zh-CN"`。
- 样式内联，不依赖外部 CDN，保证离线可读。
- 所有来自报告输入的文本必须进行 HTML 转义，禁止直接拼接未转义内容。
- 图表使用相对路径引用 `reports/figures/`，结果表使用相对路径链接 `reports/tables/`；详情页位于 `reports/final/` 时通常表现为 `../figures/...` 和 `../tables/...`。
- 图表必须有 `alt` 文本，图注包含标题和必要说明。
- 每个章节必须有稳定锚点，供结论摘要跳转：
  - 分析概览：`#overview`
  - 业务问题：`#q-q1`、`#q-q2`（ID 小写）
  - 过程章节：`#detail-d1`、`#detail-d2`（ID 小写）
  - 附录：`#appendix`
- 页面必须包含运行 ID 标记，供报告绑定校验：

```html
<meta name="dsh-run-id" content="运行 ID">
```

- 不写入真实数据库密码、密钥、token 或未脱敏敏感明细。
- 页面不得包含“待填写”“TODO”“TBD”等未完成占位内容；可选章节缺失时应使用明确的中性说明。

## 5. 与结论摘要的关系

结论摘要中的“交付物索引”必须链接到本页及对应章节锚点。本页页头必须提供返回结论摘要的链接：

```text
final_analysis_report.md
```

两份产物必须由同一次脚本执行生成，并绑定同一个正式运行 ID。
